# 工厂智能知识库系统 - 需求文档

**文档版本**: v3.0  
**更新日期**: 2026-05-13  
**项目阶段**: 立项/启动  
**技术路线**: Python + FastAPI + Next.js  

---

## 1. 项目背景与目标

### 1.1 问题现状

当前公司知识管理存在以下问题：

- **信息分散**：作业指导、物料说明、技术规范等文档分散在各部门，无统一管理平台
- **检索效率低**：获取信息需要人工查找、询问，周期长（通常需要 2-4 小时）
- **依赖人工**：文档查询和解答依赖特定人员，易形成知识孤岛
- **缺乏权限管控**：敏感文档与公开文档混存，无法按部门或人员进行访问隔离
- **缺乏追踪**：无法快速定位信息来源，问答记录难以审计

### 1.2 目标与愿景

构建**基于大模型的语义知识问答系统**，实现：

- **快速检索**：从文档库中秒级检索相关内容，目标 < 2s
- **精准问答**：基于文档语义理解，生成准确、可靠的回答
- **可追溯引用**：每个答案都标注来源文档和引用片段，支持审计
- **可见范围管控**：文档可按公开 / 部门 / 私有维度管理访问权限
- **多格式支持**：支持 PDF、Word、Excel、PowerPoint、TXT、Markdown 等常用格式

**最终目标**：将信息获取时间从**小时级**降低到**分钟级**，提升作业标准化和执行效率。

## 3. 用户与认证设计

### 3.1 角色定义

系统设两个角色：

| 角色 | 标识 | 说明 |
|------|------|------|
| 管理员 | `admin` | 可管理所有用户、部门、文档（含他人文档）；可查看全量会话记录 |
| 普通成员 | `member` | 可上传/管理自己的文档；可检索有权限的文档；只能查看自己的会话 |

### 3.2 权限矩阵

| 操作 | member | admin |
|------|:------:|:-----:|
| 登录 / 刷新 Token | ✅ | ✅ |
| 上传文档 | ✅ | ✅ |
| 检索 / 问答（按可见范围过滤） | ✅ | ✅ |
| 删除 / 修改**自己**上传的文档 | ✅ | ✅ |
| 删除 / 修改**他人**上传的文档 | ❌ | ✅ |
| 查看**自己**的会话历史 | ✅ | ✅ |
| 查看**所有人**的会话历史 | ❌ | ✅ |
| 创建 / 禁用用户 | ❌ | ✅ |
| 创建 / 管理部门 | ❌ | ✅ |

### 3.3 登录与 Token 机制

#### 登录流程

```
用户提交 {username, password}
  ↓
bcrypt 验证密码
  ↓
签发 access_token（JWT，2h 有效）
  ↓
生成 refresh_token（不透明随机串，存入 DB，30d 有效）
  ↓
返回 {access_token, refresh_token, expires_in}
```

#### Token 规格

| 类型 | 形式 | 有效期 | 存储位置 |
|------|------|--------|---------|
| Access Token | JWT（RS256 签名） | 2 小时 | 客户端内存（不写 localStorage） |
| Refresh Token | 随机 UUID，存入 DB | 30 天 | HttpOnly Cookie |

Access Token 为无状态 JWT，服务端无需存储，仅验证签名与过期时间。  
Refresh Token 存入数据库 `user_refresh_tokens` 表，登出时标记失效。

#### JWT Payload（Claims）

```json
{
  "sub":             "42",           // user.id（字符串）
  "username":        "zhangsan",
  "display_name":    "张三",
  "department_id":   "3",
  "department_name": "焊接车间",
  "role":            "member",
  "iat":             1747000000,
  "exp":             1747007200
}
```

#### 服务端鉴权流程

```
请求到达 → FastAPI 依赖注入 get_current_user()
  ↓
从 Authorization: Bearer <token> 提取 JWT
  ↓
验证签名 + 过期时间（无效则 401）
  ↓
从 claims 提取 user_id / department_id / role
  ↓
注入到下游 service 层，无需再次查 DB
```

**所有受保护的接口（除 /auth/login、/auth/refresh 外）都必须携带 Bearer Token**。viewer 身份完全由 JWT 提供，接口请求体 / 查询参数中不接受也不信任手动传入的身份字段。

### 3.4 密码策略

- 加密算法：bcrypt，cost factor = 12
- 密码复杂度：长度 ≥ 8，包含字母和数字
- 忘记密码：MVP 阶段由管理员重置，不做邮件找回

### 3.5 初始化

系统首次启动时，通过环境变量或 `alembic` 数据初始化脚本创建一个默认 admin 账户：

```
INIT_ADMIN_USERNAME=admin
INIT_ADMIN_PASSWORD=（必须在 .env 中指定，不提供默认值）
```

## 4. 文档解析规范

### 4.1 支持的文件格式

| 格式 | 扩展名 | 解析库 | 提取内容 |
|------|--------|--------|---------|
| PDF | `.pdf` | `PyMuPDF (fitz)` | 正文文本，按页提取，保留页码 |
| Word | `.docx` | `python-docx` | 段落正文、标题层级 |
| Excel | `.xlsx` | `openpyxl` | 每个 Sheet 按行列转为文本表格 |
| PowerPoint | `.pptx` | `python-pptx` | 每页幻灯片的文本框内容 |
| 纯文本 | `.txt` | stdlib | 直接读取，UTF-8 |
| Markdown | `.md` | stdlib | 直接读取，去除 Markdown 语法标记后入库 |

**超出支持范围的格式**：上传时返回 `400 Unsupported file type`，不允许存储。

### 4.2 分块策略

- 默认分块大小：512 tokens（tiktoken `cl100k_base` 编码）
- 重叠窗口：128 tokens
- PDF 额外保留**页码**元数据（`source_location` 字段），用于引用定位
- Excel / PPTX 额外保留**来源标识**（Sheet 名 / 幻灯片编号）

### 4.3 文档处理流水线

```
用户上传文件（附 Bearer Token）
  ↓
JWT 验证 → 提取 uploader_id、department_id
  ↓
校验文件格式（白名单）
  ↓
上传原文件至 MinIO → 返回 object_key
  ↓
插入文档记录（status = processing，保存 object_key + 可见范围）
  ↓
按格式调用对应解析器提取文本
  ↓
tiktoken 分块，记录每块 token 数和位置信息
  ↓
批量调用通义 Embedding API（每批 25 条）
  ↓
事务内：
  - 批量写入 document_chunks（含位置元数据）
  - Qdrant upsert 向量点（含完整 payload，含权限字段）
  ↓
更新文档状态 → completed
  ↓
返回文档信息
```

## 5. 对象存储设计

### 5.1 存储方案

使用 **MinIO** 作为本地部署的对象存储，暴露 S3 兼容 API。后续可无缝迁移至阿里云 OSS、AWS S3 等云存储，仅需修改连接配置。

系统不在本地文件系统保留文档原文，所有上传的原始文件统一存入 MinIO。数据库只保存 `object_key`（对象路径），下载时通过 MinIO 生成预签名 URL。

### 5.2 存储桶设计

| Bucket | 用途 | 访问策略 |
|--------|------|---------|
| `factory-documents` | 存储所有上传的原始文档 | 私有，通过预签名 URL 访问 |

### 5.3 对象命名规范

```
{document_id}/{yyyyMMdd-HHmmss}_{original_filename}

示例：
  42/20260513-143022_作业指导_焊接.pdf
```

### 5.4 相关操作

| 操作 | 说明 |
|------|------|
| 上传 | 服务端接收文件后直接 put_object 到 MinIO |
| 下载 | 服务端验证权限后生成 presigned_url（有效期 1 小时），前端直接从 MinIO 下载 |
| 删除 | 删除文档时同步删除 MinIO 对象 |

## 6. 可见范围设计

### 6.1 三级可见范围

| 级别 | 标识符 | 说明 |
|------|--------|------|
| 公开 | `public` | 所有已登录用户均可检索和查看 |
| 部门 | `department` | 仅与文档 `department_id` 相同的用户可检索和查看 |
| 私有 | `private` | 仅上传者本人可检索和查看（admin 除外） |

### 6.2 对检索的影响

用户发起检索或问答时，身份来自 JWT Claims（`user_id`、`department_id`、`role`）。系统在 Qdrant 查询时自动拼接以下过滤条件：

```
若 role = 'admin'：不施加可见范围过滤（admin 可见全量）

若 role = 'member'：
  visibility_scope = 'public'
  OR (visibility_scope = 'department' AND department_id = <JWT.department_id>)
  OR (visibility_scope = 'private' AND uploader_id = <JWT.user_id>)
```

可见范围元数据随向量点一起存入 Qdrant payload，过滤在向量召回前完成，无二次过滤，性能无损。

### 6.3 上传时的可见范围参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `visibility` | `public` \| `department` \| `private` | 是 | 可见范围 |
| `tags` | `string[]` | 否 | 文档标签，用于过滤检索 |

`department_id` 不由上传者指定，由服务端从 JWT 中提取，防止跨部门伪造。

## 7. 向量检索与元数据过滤

### 7.1 Qdrant Payload 设计

每个向量点的 payload 包含以下字段，全部支持过滤：

```json
{
  "document_id":      "integer — 文档 ID",
  "chunk_id":         "integer — 分块 ID（与关系库主键一致）",
  "chunk_index":      "integer — 分块在文档中的序号",
  "document_name":    "string  — 原始文件名",
  "file_type":        "string  — pdf / docx / xlsx / pptx / txt / md",
  "uploader_id":      "integer — 上传者 user.id",
  "department_id":    "integer — 所属部门 ID（可为 null，仅 public 时）",
  "visibility_scope": "string  — public / department / private",
  "tags":             "string[] — 文档标签",
  "upload_date":      "integer — Unix 时间戳，支持范围过滤",
  "source_location":  "string  — 来源位置，如'第3页'、'Sheet1'、'幻灯片5'",
  "snippet":          "string  — 分块前 200 字符，用于引用展示"
}
```

### 7.2 检索接口过滤参数

viewer 身份由 JWT 自动注入，请求体只需传业务过滤条件：

```json
POST /api/v1/search
{
  "query":            "如何进行焊接质量检查？",
  "top_k":            5,
  "score_threshold":  0.6,

  "filter": {
    "file_types":       ["pdf", "docx"],
    "uploader_ids":     [3, 7],
    "department_ids":   [2],
    "tags":             ["质量标准"],
    "upload_date_from": "2026-01-01",
    "upload_date_to":   "2026-05-13",
    "document_ids":     [1, 2, 3]
  }
}
```

### 7.3 过滤执行顺序

```
1. 从 JWT 解析 user_id / department_id / role
2. 构建权限 Filter（按 6.2 节规则）
3. 与用户自定义 filter 合并（must AND）
4. 将合并后的 Filter 传入 Qdrant 向量检索
5. Qdrant 在满足条件的子集内执行 ANN 搜索，返回 topK 结果
```

## 8. 问答会话存储设计

### 8.1 设计原则

问答记录属于**追加写入、按会话读取**的访问模式，不需要复杂的关联查询。存储方案需满足：

- 按 `session_id` 追加写入对话轮次
- 按 `session_id` 顺序读取完整对话链
- 支持列出最近 N 个会话（倒序）
- 对话内容包含结构化引用信息

### 8.2 推荐方案：PostgreSQL JSONB

使用 **PostgreSQL** 作为统一的关系数据库，利用 JSONB 字段存储每轮对话的灵活内容，兼顾结构化查询与 schema 灵活性。

```
qa_sessions 表（结构化部分）
  - session_id:     UUID 主键
  - user_id:        发起人（FK → users.id，来自 JWT）
  - turn_count:     轮次计数
  - created_at / last_active_at

qa_records 表（每轮对话）
  - id:         主键
  - session_id: 外键
  - turn_id:    该会话的轮次序号
  - question:   问题文本
  - answer:     回答文本
  - context:    JSONB — 存储本轮引用 + 检索参数 + token 用量等扩展信息
  - created_at
```

`context` 字段示例：

```json
{
  "citations": [
    {
      "chunk_id":       789,
      "document_name":  "作业指导_焊接.pdf",
      "source_location":"第 3 页",
      "snippet":        "内部缺陷检查需要使用超声波检测..."
    }
  ],
  "retrieval_filter": { "department_ids": [2], "file_types": ["pdf"] },
  "tokens_used":      1842,
  "model":            "deepseek-chat",
  "window_reduced":   false
}
```

### 8.3 备选方案

| 方案 | 适用场景 |
|------|---------|
| **SQLite + JSON 字段** | 轻量本地部署、单机运行 |
| **MongoDB** | 需要更复杂的文档查询 |

推荐生产默认选用 **PostgreSQL**，开发环境可切换为 SQLite，仅修改 `DATABASE_URL`。

## 11. 接口规范

所有接口（除 `/auth/login`、`/auth/refresh` 外）均需携带：

```
Authorization: Bearer <access_token>
```

未携带或 Token 无效返回 `401 Unauthorized`，无权限操作返回 `403 Forbidden`。

### 11.1 认证接口

#### 登录


## 12. 数据模型

### 12.1 PostgreSQL 表结构

```sql
-- 部门表
CREATE TABLE departments (
    id         BIGSERIAL PRIMARY KEY,
    name       VARCHAR(100) NOT NULL UNIQUE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 用户表
CREATE TABLE users (
    id            BIGSERIAL PRIMARY KEY,
    username      VARCHAR(100) NOT NULL UNIQUE,
    display_name  VARCHAR(100) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    department_id BIGINT REFERENCES departments(id),
    role          VARCHAR(20)  NOT NULL DEFAULT 'member', -- member / admin
    is_active     BOOLEAN      NOT NULL DEFAULT TRUE,
    created_at    TIMESTAMPTZ  DEFAULT NOW(),
    updated_at    TIMESTAMPTZ  DEFAULT NOW()
);
CREATE INDEX idx_users_username      ON users(username);
CREATE INDEX idx_users_department_id ON users(department_id);

-- Refresh Token 表（登出时标记失效）
CREATE TABLE user_refresh_tokens (
    id         BIGSERIAL PRIMARY KEY,
    user_id    BIGINT      NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token      VARCHAR(128) NOT NULL UNIQUE,
    expires_at TIMESTAMPTZ NOT NULL,
    revoked    BOOLEAN     NOT NULL DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_refresh_token ON user_refresh_tokens(token);

-- 文档表
CREATE TABLE documents (
    id            BIGSERIAL PRIMARY KEY,
    file_name     VARCHAR(255) NOT NULL,
    file_type     VARCHAR(20)  NOT NULL,
    object_key    VARCHAR(512) NOT NULL,           -- MinIO 对象路径
    uploader_id   BIGINT       NOT NULL REFERENCES users(id),
    department_id BIGINT       REFERENCES departments(id),
    visibility    VARCHAR(20)  NOT NULL DEFAULT 'public',
    tags          TEXT[],
    upload_time   TIMESTAMPTZ  NOT NULL,
    file_size     BIGINT,
    status        VARCHAR(20)  NOT NULL DEFAULT 'processing',
    error_message TEXT,
    created_at    TIMESTAMPTZ  DEFAULT NOW(),
    updated_at    TIMESTAMPTZ  DEFAULT NOW()
);
CREATE INDEX idx_documents_uploader_id   ON documents(uploader_id);
CREATE INDEX idx_documents_department_id ON documents(department_id);
CREATE INDEX idx_documents_visibility    ON documents(visibility);
CREATE INDEX idx_documents_file_type     ON documents(file_type);

-- 文档分块表
CREATE TABLE document_chunks (
    id              BIGSERIAL PRIMARY KEY,
    document_id     BIGINT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index     INT    NOT NULL,
    chunk_content   TEXT   NOT NULL,
    tokens          INT,
    source_location VARCHAR(255),
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE (document_id, chunk_index)
);
CREATE INDEX idx_chunks_document_id ON document_chunks(document_id);

-- 会话表
CREATE TABLE qa_sessions (
    session_id     VARCHAR(50) PRIMARY KEY,
    user_id        BIGINT      NOT NULL REFERENCES users(id),
    turn_count     INT         NOT NULL DEFAULT 0,
    created_at     TIMESTAMPTZ DEFAULT NOW(),
    last_active_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_sessions_user_id     ON qa_sessions(user_id);
CREATE INDEX idx_sessions_last_active ON qa_sessions(last_active_at DESC);

-- 问答记录表（context 为 JSONB，存储引用、检索参数、token 用量等扩展信息）
CREATE TABLE qa_records (
    id         BIGSERIAL PRIMARY KEY,
    session_id VARCHAR(50) NOT NULL REFERENCES qa_sessions(session_id) ON DELETE CASCADE,
    turn_id    INT         NOT NULL,
    question   TEXT        NOT NULL,
    answer     TEXT        NOT NULL,
    context    JSONB       NOT NULL DEFAULT '{}',
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE (session_id, turn_id)
);
CREATE INDEX idx_records_session_id ON qa_records(session_id);
CREATE INDEX idx_records_context    ON qa_records USING gin(context);

-- 系统配置表
CREATE TABLE system_config (
    config_key   VARCHAR(100) PRIMARY KEY,
    config_value VARCHAR(1024) NOT NULL,
    description  VARCHAR(255),
    updated_at   TIMESTAMPTZ DEFAULT NOW()
);
```

### 12.2 Qdrant 集合设计

```
Collection: factory_chunks
  Distance:          Cosine
  Vector Size:       1024（text-embedding-v3）
  on_disk_payload:   true

Payload 字段（全部支持 filter）：
  document_id       integer
  chunk_id          integer   ← Point ID，与 document_chunks.id 一致
  chunk_index       integer
  document_name     string
  file_type         string
  uploader_id       integer   ← 用于 private 可见范围过滤
  department_id     integer   ← 用于 department 可见范围过滤（可为 null）
  visibility_scope  string    ← public / department / private
  tags              string[]
  upload_date       integer   ← Unix 时间戳
  source_location   string
  snippet           string    ← 分块前 200 字符
```

```
Bucket: factory-documents

示例：
```

## 13. 多轮对话策略

### 13.1 滑动窗口

- 默认回溯最近 **5 轮**对话（`CHAT_HISTORY_WINDOW` 配置）
- 从 `qa_records` 按 `turn_id DESC LIMIT N` 查询，反转后插入 messages
- 每轮对话对应一对 `user` / `assistant` 消息

### 13.2 Prompt 结构

```
[system]  你是一个工厂知识库助手，只基于提供的参考资料回答问题。
           如果参考资料中没有相关信息，明确告知用户。
           回答要结构清晰，引用资料中的原文支撑观点。

[user]    Q1（历史）
[assistant] A1（历史）
...
[user]    Q_N（历史）
[assistant] A_N（历史）

[user]    {当前问题}

          参考资料：
          [文档: xxx.pdf，来源: 第3页]
          {chunk_content}
          ...
```

### 13.3 Token 超限处理

当 DeepSeek API 返回 `context_length_exceeded` 时，自动将历史窗口缩小 1 轮后重试，最多缩小至 1 轮。缩小事件记录到 `qa_records.context.window_reduced = true`，用于后续分析。

## 14. 非功能需求

| 类别 | 要求 |
|------|------|
| **性能** | 检索 < 2s，问答生成 < 5s（含 DeepSeek 响应） |
| **并发** | 支持 ≥ 50 并发用户（FastAPI + asyncio 原生支持） |
| **可靠性** | 系统可用性 ≥ 95% |
| **安全** | 密码 bcrypt 哈希；JWT RS256 签名；refresh_token HttpOnly Cookie；接口权限分层校验 |
| **存储** | 文档原文存 MinIO，关系数据存 PostgreSQL，向量存 Qdrant |

| **可观测** | 每个关键步骤（登录、上传、解析、向量化、检索、生成）记录结构化日志 |

## 15. 风险与应对

| 风险 | 应对方案 |
|------|---------|
| JWT 泄露 | access_token 存客户端内存（不写 localStorage）；refresh_token 用 HttpOnly Cookie；access_token TTL 仅 2h |
| refresh_token 被盗用 | 数据库存储 + 登出即失效；可扩展为 token rotation 策略 |
| admin 账户弱密码 | 初始密码通过 .env 强制配置，不提供默认值；首次登录强制修改 |
| PDF 扫描件无文字层 | 标记为 OCR 待处理，当前版本跳过，返回 `parse_warning` |
| XLSX/PPTX 内容为图片 | 提取可识别文本，空白则标记 `parse_warning` |
| MinIO 故障 | 文档上传整体失败，返回 503；已入库文档不受影响（object_key 已记录） |
| Qdrant payload filter 召回率低 | 日志记录 filter + 召回数；提示用户放宽过滤条件 |
| 多轮对话上下文累积偏差 | 前端支持"新对话"重置；展示历史供用户审核 |

## 16. 验收标准

| 场景 | 验收条件 |
|------|---------|
| 登录 | 正确密码返回 access_token + HttpOnly refresh_token cookie |
| 无效 Token 访问 | 返回 401，不泄露任何业务数据 |
| member 访问他人私有文档 | 检索结果中不出现，GET /download 返回 403 |
| admin 访问任意文档 | 检索可见全量，GET /download 正常返回 |
| 上传 PDF | MinIO 有对象，Qdrant 有向量点，source_location 包含页码 |
| 上传 XLSX | source_location 包含 Sheet 名 |
| 按格式过滤检索 | `filter.file_types=["pdf"]` 结果中不出现非 PDF 文档 |
| 部门可见范围 | `visibility=department, department_id=A` 的文档，department_id=B 的用户检索不到 |
| 私有文档 | `visibility=private` 仅上传者本人检索可见，admin 亦可见 |
| 多轮对话 | 第 2 轮发至 DeepSeek 的 messages 包含第 1 轮 Q&A |
| 删除文档 | PostgreSQL 记录、Qdrant 向量点、MinIO 对象三者同步删除 |
| member 删除他人文档 | 返回 403 |
| 登出 | refresh_token 失效，刷新接口返回 401 |

## 17. 启动指南

```bash
# 1. 启动基础服务（PostgreSQL + Qdrant + MinIO）
docker-compose up -d postgres qdrant minio

# 2. 配置环境变量
cp backend/.env.example backend/.env
# 必填：DEEPSEEK_API_KEY、DASHSCOPE_API_KEY、DATABASE_URL
# 必填：MINIO_*、JWT_PRIVATE_KEY（RS256 私钥路径）
# 必填：INIT_ADMIN_USERNAME、INIT_ADMIN_PASSWORD

# 3. 数据库迁移（含创建默认 admin 账户）
cd backend && alembic upgrade head

# 4. 启动后端（Swagger 文档：http://localhost:8000/docs）
uvicorn app.main:app --reload

# 5. 启动前端（http://localhost:3000）
cd frontend && npm install && npm run dev
```
