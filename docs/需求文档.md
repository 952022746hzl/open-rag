## 1. 项目背景与目标

### 1.1 问题现状

当前公司知识管理存在以下问题：

- **信息分散**：作业指导、物料说明、技术规范等文档分散在各部门，无统一管理平台
- **检索效率低**：获取信息需要人工查找、询问，周期长（通常需要 2-4 小时）
- **依赖人工**：文档查询和解答依赖特定人员，易形成知识孤岛
- **缺乏权限管控**：敏感文档与公开文档混存，无法按部门或人员进行访问隔离
- **缺乏追踪**：无法快速定位信息来源，问答记录难以审计

### 1.2 目标与愿景

构建**基于大模型的语义知识问答系统**，实现：

- **快速检索**：从文档库中秒级检索相关内容，目标 < 2s
- **精准问答**：基于文档语义理解，生成准确、可靠的回答
- **可追溯引用**：每个答案都标注来源文档和引用片段，支持审计
- **可见范围管控**：文档可按公开 / 部门 / 私有维度管理访问权限
- **多格式支持**：支持 PDF、Word、Excel、PowerPoint、TXT、Markdown 等常用格式

**最终目标**：将信息获取时间从**小时级**降低到**分钟级**，提升作业标准化和执行效率。

### 1.3 术语表

| 术语 | 定义 |
|------|------|
| 分块（Chunk） | 文档解析后的最小检索单元，每块约 512 tokens，相邻分块有 128 tokens 重叠 |
| 向量（Embedding） | 文本经模型处理后得到的 1024 维数值向量，用于语义相似度计算 |
| Qdrant Payload | 向量点关联的结构化元数据，支持过滤查询，包含权限、来源、标签等字段 |
| 会话（Session） | 用户一次连续的多轮问答交互，由 `session_id` 唯一标识 |
| 可见范围（visibility） | 文档访问控制级别：`public`（所有登录用户）、`department`（同部门用户）、`private`（仅上传者本人及 admin） |
| visibility_scope | Qdrant payload 中的可见范围字段，与文档表 `visibility` 字段含义相同；分层命名以区分来源 |
| object_key | 文档原文在 MinIO 中的对象路径，格式：`{document_id}/{yyyyMMdd-HHmmss}_{filename}` |
| Access Token | JWT（RS256），有效期 2h，存于前端内存，用于 API 身份鉴权 |
| Refresh Token | 随机不透明令牌，有效期 30d，存于 HttpOnly Cookie，用于换取新 Access Token |
| ANN | Approximate Nearest Neighbor，近似最近邻搜索，Qdrant 执行向量相似度检索的算法 |
| top_k | 检索返回的最大分块数量，默认值见各接口定义 |
| score_threshold | 向量相似度得分下限，低于此值的候选分块被过滤；默认 0.6 |
| uploader_id | 上传者 `user.id`，来自 JWT claims，用于 `private` 权限过滤 |
| department_id | 部门 ID，来自 JWT claims，用于 `department` 权限过滤；用户未分配部门时为 null |

## 2. 功能需求

### 2.1 核心功能清单

| 功能模块 | 描述 | MVP | 优先级 |
|---------|------|-----|--------|
| 用户注册 / 登录 | 用户名密码登录，颁发 JWT，支持 Token 刷新 | ✅ | P0 |
| 多格式文档上传 | 支持 PDF / DOCX / XLSX / PPTX / TXT / MD，自动解析内容 | ✅ | P0 |
| 对象存储 | 文档原文存入 MinIO，系统仅保存对象路径引用 | ✅ | P0 |
| 向量化存储 | 文档分块后生成 Embedding，带元数据存入 Qdrant | ✅ | P0 |
| 元数据过滤检索 | 检索时可按文档来源、部门、日期、标签等字段过滤 | ✅ | P0 |
| 可见范围管控 | 文档设置 public / department / private 三级可见范围 | ✅ | P0 |
| 智能问答 | 调用 DeepSeek API，基于检索结果生成答案 | ✅ | P0 |
| 多轮对话 | 滑动窗口保留最近 N 轮历史，作为上下文传入 LLM | ✅ | P0 |
| 答案溯源 | 回答中标注引用来源（文档名、片段位置） | ✅ | P0 |
| 文档管理 | 查看文档列表、更新元数据、删除文档 | ✅ | P1 |
| 问答历史记录 | 记录所有会话，支持回放完整对话链 | ✅ | P1 |
| 用户管理（admin） | 管理员创建/禁用用户、调整角色和部门 | ✅ | P1 |

### 2.2 阶段化实现计划

#### 第一阶段：用户认证 + 文档上传存储
- 用户注册/登录，JWT 颁发与校验
- 部门管理（admin）
- 多格式文档解析（PDF / DOCX / XLSX / PPTX / TXT / MD）
- MinIO 对象存储集成
- 文档元数据持久化（含可见范围字段）

#### 第二阶段：向量化与元数据过滤检索
- 通义 Embedding 批量向量化
- Qdrant payload 元数据写入（含权限字段）
- 带过滤条件的语义检索接口

#### 第三阶段：智能问答与多轮对话
- DeepSeek 问答接口集成
- 会话管理与滑动窗口上下文
- 问答历史存储方案落地

#### 第四阶段：前端界面
- Next.js 三页面（对话 / 文档管理 / 历史会话）
- 登录页 + Token 存储
- 文档上传 + 可见范围配置 UI
- 检索过滤条件 UI
