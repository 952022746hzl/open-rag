## Qdrant Payload 设计

每个向量点的 payload 包含以下字段，全部支持过滤：

```json
{
  "document_id":      "integer — 文档 ID",
  "chunk_id":         "integer — 分块 ID（与关系库主键一致）",
  "chunk_index":      "integer — 分块在文档中的序号",
  "document_name":    "string  — 原始文件名",
  "file_type":        "string  — pdf / docx / xlsx / pptx / txt / md",
  "uploader_id":      "integer — 上传者 user.id",
  "department_id":    "integer — 所属部门 ID（可为 null，当上传者无部门归属时）",
  "visibility_scope": "string  — public / department / private",
  "tags":             "string[] — 文档标签",
  "upload_date":      "integer — Unix 时间戳，支持范围过滤",
  "source_location":  "string  — 来源位置，如'第3页'、'Sheet1'、'幻灯片5'",
  "snippet":          "string  — 分块前 200 字符，用于引用展示"
}
```

## 检索接口过滤参数

viewer 身份由 JWT 自动注入，请求体只需传业务过滤条件：

```json
POST /api/v1/search
{
  "query":            "如何进行焊接质量检查？",
  "top_k":            5,
  "score_threshold":  0.6,

  "filter": {
    "file_types":       ["pdf", "docx"],
    "uploader_ids":     [3, 7],
    "department_ids":   [2],
    "tags":             ["质量标准"],
    "upload_date_from": "2026-01-01",
    "upload_date_to":   "2026-05-13",
    "document_ids":     [1, 2, 3]
  }
}
```

> **日期过滤格式说明**：`upload_date_from` 和 `upload_date_to` 接受 ISO 8601 日期格式（`YYYY-MM-DD`），服务端在构建 Qdrant 过滤条件时将其转换为 Unix 时间戳（取当日 00:00:00 UTC 和 23:59:59 UTC），与 payload 中 `upload_date`（integer）做范围比较。

## 过滤执行顺序

```
1. 从 JWT 解析 user_id / department_id / role
2. 构建权限 Filter（按可见范围控制规则）
3. 与用户自定义 filter 合并（must AND）
4. 对查询词分别计算稠密向量（text-embedding-3-small）和稀疏向量（fastembed BM25）
5. 双路 Prefetch（各取 top_k × OVERSAMPLING_FACTOR）：
     - Dense Prefetch：稠密 ANN 搜索，施加合并 Filter + score_threshold
     - Sparse Prefetch：BM25 关键字搜索，施加合并 Filter，不设阈值
6. Qdrant 服务端 RRF 融合两路结果（query_points + FusionQuery）
7. 服务端按 document_id 分组，取每组最高分排序文档
8. 每个文档最多保留 SEARCH_CHUNKS_PER_DOC 个 chunk，裁剪至 top_k 返回
```

---

## 混合检索策略（稠密 + 稀疏）

系统采用 **dense + sparse** 双路混合检索，通过 RRF 融合：

| 路径 | 模型 | 擅长场景 |
|------|------|---------|
| Dense | text-embedding-3-small（1536 维） | 语义相似、同义词、上下文理解 |
| Sparse | fastembed BM25（CJK character-level） | 命名实体、人名、专有名词精确匹配 |

**RRF 融合**：对两路各自的排名位置计算 `1/(k+rank)` 之和（k=60），分数与余弦相似度量纲不同；`score_threshold` 仅施加于 dense prefetch，sparse 不设阈值以保障关键字召回。

---

## 过采样与文档分组策略

单纯向量相似度排名会导致高相关文档的后续 chunk（不含查询词的页面）被其他文档的 chunk 挤出 top_k。
为此引入两个服务端参数（`.env` 可覆盖）：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `SEARCH_OVERSAMPLING_FACTOR` | 5 | 内部搜索量 = top_k × 倍率，扩大候选池 |
| `SEARCH_CHUNKS_PER_DOC` | 3 | 单文档最多返回 chunk 数，避免被单一文档独占 |

**效果**：`top_k=5` 时，最高分文档最多占 3 个槽，其余文档各占 1 个槽，兼顾深度召回与多样性。
